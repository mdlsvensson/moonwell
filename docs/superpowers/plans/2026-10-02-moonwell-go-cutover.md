# Moonwell in Go, Plan 5e: The Cutover — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.
> Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Moonwell 0.8.0: the generators in Go, the TypeScript, `cli/` and every `deno.json` deleted, the install
scripts, the release workflow, the documents, and the release with its gate.

**Architecture:** `tools/gen` is one program with four modes; its parsers are packages below it. Everything else in
this plan removes, moves or documents: the Go code of Plans 5a to 5d is already the whole CLI.

**Tech Stack:** Go 1.27, standard library only. PowerShell 5.1 and POSIX `sh` for the two install scripts. GitHub
Actions for the release.

**Spec:** `docs/superpowers/specs/2026-10-02-moonwell-go-toolchain-design.md` (§3 the layout, §7 to §9, §11, §12).

**How to read the tasks.** As Plans 5a to 5d: each task's specification is the TypeScript it names and the Go
interface given here; a task is done when its inventory rows are ported and pass. Test-first.

## Global Constraints

- Standard library only. `gofmt -l .` prints nothing; `go vet ./...` and `go test ./...` pass before every commit.
- The generators' output is byte-identical to the TypeScript generators', except the first line of each
  `schema/generated/*.pkl` (see Decisions).
- The conformance suite's last green run on both systems is commit `f82dd66` (CI run 37007905168). Nothing
  in `internal/` changes its behaviour after that commit in this plan; texts in `template/` that name Deno do.
- Release tags are `moonwell@<version>`.
- Go is not on the PATH of the agent's shell: `export PATH="$PATH:/c/Program Files/Go/bin"`.

## Decisions

- **The generated header changes.** Each `schema/generated/*.pkl` starts with
  ``// GENERATED by `deno task gen` from cli/data/metadata.json (game …) — do not edit.`` Both the command and the
  path are gone after this plan, so the line becomes
  ``// GENERATED by `go run ./tools/gen` from data/metadata.json (game …) — do not edit.`` The Go generator is first
  run with the old line, which must leave the seven files unchanged (the byte-identity check of spec §9); then the
  line is changed and the files are regenerated, and the diff is those seven lines.
- **`gen metadata` takes the game version,** like today's `deno task gen:metadata <folder> <version>`: the version
  is written into the file. The spec's table (§9) left it out.
- **The three data files are checked twice.** A test renders the committed `data/natives.json` and
  `data/metadata.json` again from their parsed content and compares the bytes, which pins the two renderers without
  game files. And the maintainer's exports are at hand (`~/Downloads/Work` for the scripts,
  `~/moonwell-game-data/3.0.0.24268` for the object data, `~/Downloads/exported-listfile.txt` for the paths), so all
  three are regenerated once and must not change.
- **A value the game's data never has fails the generator** instead of writing `null`: a `repeat` or `data` cell
  that is not a number. JavaScript wrote `NaN`, which `JSON.stringify` turns into `null`.
- **The handwritten inputs stay where they are:** `tools/natives/lua-extras.json` and
  `tools/metadata/overrides.json`.
- **The install scripts carry the version literally** (`0.8.0`), and `module_test.go` checks that `version.go`,
  `schema/PklProject` and both scripts agree. The release workflow uploads them as they are. Each has one testing
  seam, the environment variable `MOONWELL_INSTALL_BASE` (where to download from), and the Windows script skips the
  PATH change when `MOONWELL_INSTALL_NO_PATH` is `1`. Neither is documented for users.
- **The Pkl schema's own tests** (`pkl test schema/tests/Project.pkl schema/tests/Objects.pkl`), which
  `deno task test:pkl` ran, become a Go test at the root that runs `pkl test`.
- **The gate comes before the tag** for the game steps, as in every release so far: the maintainer runs steps 1 to
  6 with a `moonwell` built from the checkout (`go build ./cmd/moonwell`). The install step can only run after the
  release exists; the release workflow runs it on both systems, and the maintainer runs it once on their machine
  (with the SmartScreen check of spec §8.2).
- **The sibling repositories' Deno tools stop working** when `cli/` is deleted, until Plan 5f, which follows at
  once.

## Amendments made while implementing

- **The checks of a release are `ci.yml` itself:** it gained a `workflow_call` trigger, and `release.yml` calls it,
  so the two cannot drift apart.
- **The release's notes** are the changelog's section for the version, up to its first `###` heading, with a link to
  the changelog.
- **`template/moonwell.local.pkl` is not a tracked file** (it is git-ignored; `init` writes the text from
  `project.LocalPkl`), so only `template/moonwell.pkl` and `template/yueconfig.yue` changed their comments.
- **The install scripts refuse four cases** in their test: a wrong checksum, a file the checksums do not list, a
  missing download and missing checksums. Each leaves the installed file as it was.
- **`internal/cli/unit_test.go`** compared the `PklProject` that `init` writes with a literal `0.7.0` in a condition
  that could not fail; it now compares with `moonwell.Version`.

### Task 1: The parsers

**Reference:** `tools/metadata/slk.ts`, `tools/metadata/txt.ts`, `tools/natives/jass.ts`.

**Produces:**

```go
package slk
// Row is one record after the header row: its cells in column order.
type Row struct{ /* … */ }
func (r Row) Get(column string) (string, bool)
func (r Row) Value(column string) string // "" when the cell is absent
func (r Row) First() string              // the first cell's text, for messages
type Table struct { Columns []string; Rows []Row }
func Parse(text, file string) (Table, error)

package ini
// File maps section names to their keys, both in the order they first appear.
type File = ordered.Map[*ordered.Map[string]]
func Parse(text string, into *File) *File // nil starts a new one

package jass
type Param struct{ Type, Name string }
type Function struct { Name, Source string; Constant bool; Params []Param; Returns string }
type Global struct { Name, Source, Type string; Constant, Array bool }
type Type struct{ Name, Extends string }
type File struct { Types []Type; Functions []Function; Globals []Global }
func Parse(text, source string) (File, error)
```

- [x] JavaScript's `\s` and `.trim()` are `text.SpaceClass` and `text.Trim`; `JSON.stringify` is `text.Quote`.
- [x] Commit: `go: the generators' parsers`.
